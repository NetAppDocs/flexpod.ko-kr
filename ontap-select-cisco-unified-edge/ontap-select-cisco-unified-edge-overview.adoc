= Cisco Unified Edge에 ONTAP Select 배포
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
전용 NetApp 어플라이언스에 대한 소프트웨어 정의 스토리지 대안으로, ONTAP Select는 지원되는 하이퍼바이저(KVM 또는 VMware vSphere)에서 가상 머신으로 실행되며 로컬에 연결된 스토리지를 사용하여 NAS 및 SAN 서비스를 제공합니다. ONTAP Select는 원격 사무실, 백오피스, 맞춤형 엣지 구축, 모바일 환경 등 고객이 ONTAP 데이터 서비스의 모든 기능을 활용하고자 하는 다양한 시나리오에 적합합니다.


NOTE: Cisco Unified Edge의 ONTAP Select(OTS)는 고가용성(HA) 없이 단일 노드 인스턴스로 배포됩니다.

ONTAP Select와 Cisco Unified Edge를 함께 배포하면 통합 에지 아키텍처가 구축됩니다. 스토리지에 최적화된 컴퓨팅 노드가 로컬 NVMe 미디어를 제공합니다. 하이퍼바이저는 ONTAP Select 가상 머신에 적절한 리소스를 제공합니다. ONTAP Select는 로컬 미디어를 ONTAP 애그리게이트 및 볼륨으로 구성하여 동일한 섀시 또는 에지 사이트의 다른 위치에서 로컬로 실행되는 애플리케이션 워크로드에 스토리지를 제공합니다. 이러한 설계는 데이터를 애플리케이션 가까이에 유지하고, 일상적인 운영에서 WAN 연결에 대한 의존도를 줄이며, 중앙 집중식 관리 및 데이터 보호 정책과 일치합니다.

image::ots-on-cue.png[Cisco Unified Edge 아키텍처의 ONTAP Select]

XE130c 및 XE150c 컴퓨팅 노드의 4개 드라이브 제한과 소프트웨어 RAID 의존성으로 인해 ONTAP Select 구축은 단일 컨트롤러 아키텍처로 제한됩니다. 컨트롤러 페일오버 기능을 갖춘 멀티 노드 스토리지 아키텍처와 달리, 단일 스토리지 컨트롤러는 호스팅하는 로컬 스토리지 서비스에 영향을 주지 않고 컨트롤러 수준 유지 관리를 위해 오프라인으로 전환할 수 없습니다.

이러한 제약 조건이 아키텍처의 가치를 없애는 것은 아니지만, 운영 모델에 반영되어야 합니다. 적합한 워크로드는 계획된 스토리지 중단을 허용하거나, 애플리케이션 수준의 복원력을 활용하거나, 복구를 위해 중앙 ONTAP 환경으로 복제를 사용하는 워크로드입니다. 고객은 유지 관리 일정을 정의하고, 애플리케이션 소유자에게 서비스 기간을 알리고, 중단 작업 전에 현재 백업 또는 복제본을 확인하고, 롤백 절차를 문서화해야 합니다. 워크로드가 컨트롤러 유지 관리 중에도 지속적인 스토리지 가용성을 필요로 하는 경우, 고객은 단일 컨트롤러 ONTAP Select 구성 대신 외부 ONTAP 스토리지 어레이를 평가해야 합니다.
